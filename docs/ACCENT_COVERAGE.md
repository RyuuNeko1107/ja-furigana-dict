## 埋める手段の検討

### A. UniDic の固有名詞行を使う → 実施済 (2026-09-13)

`--include-proper` を追加して 562 件付与。 東京 [0] / 中国 [1] / 関西 [1] /
福岡 [2] / 博多 [0] など地名由来の一般語が埋まった。

### B. VOICEVOX (Open JTalk) から accent を借りる → **保留**

VV は複合語の accent を返すので、 未付与の頻出 400 語に問い合わせ、
**読みが dict と一致する 168 語** で accent を取得できることを実測した
(頑張 [3] / 一回 [2] / 守護神 [2] / 外国人 [4] / 宇宙人 [3] / 時間帯 [5] …)。

ただし採用は見送った。 理由:

- Open JTalk の accent は権威データではなく、 一回 [2] / 時間帯 [5] など
  疑わしい値が混じる
- **裏取りに使える第 2 のオラクルが無い**。 lib の `--estimate-accent` は
  ADR-0007 のとおり外来語と人名にしか効かず、 漢語複合語では phrase を返さない
- 間違った accent は 「accent 無し」 より悪い (音声エンジン側の推定が使えなくなる)

→ 権威ある accent データ (NHK 日本語発音アクセント新辞典 等) を入手できたときに、
VV 由来の候補を 「答え合わせ」 して採用するのが筋。 候補の取り方は
`_analysis` ではなくこの手順書に残す (再現可能)。

### C. 複合語 accent の結合規則を実装する → 大きめの設計課題

「後部要素が 1-2 拍なら前部要素の末尾に核」 のような規則はあるが例外が多く、
数千語に一括適用すると系統的な誤りを生む。 lib 側の機能として単独 session で
設計・検証すべき。

## 再現手順

```sh
# UniDic kana-accent 2.1.2 (144MB) を取得して lex.csv を取り出す
curl -o unidic_ka.zip https://clrd.ninjal.ac.jp/unidic_archive/cwj/2.1.2/unidic-mecab_kana-accent-2.1.2_src.zip
python -c "import zipfile;zipfile.ZipFile('unidic_ka.zip').extract('unidic-mecab_kana-accent-2.1.2_src/lex.csv')"

# 付与 (固有名詞行も使う)
python tools/gen_accent_brackets.py --lex unidic-mecab_kana-accent-2.1.2_src/lex.csv     --include-proper --apply core/jukugo
```
